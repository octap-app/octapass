Octa Pass مبني لكنه لم يُطلق بعد، ولم يخضع لمراجعته الخارجية. هذا أنسب وقت للتأثير فيه.

## طرق المساعدة

| المجال | الطريقة |
|---|---|
| **مراجعة التصميم** | اقرأ [نظرة عامة على الأمان](/ar/docs/security/overview/) و[نموذج التهديدات](/ar/docs/security/threat-model/) وافتح issue بأي شيء يبدو خاطئًا. نرحّب خصوصًا بخبراء التشفير ومهندسي الأمان. |
| **التوثيق** | أصلح الصفحات غير الواضحة، وأضف أدلة الاستيراد، وحسّن الأمثلة. راجع [كتابة التوثيق](/ar/docs/contributing/writing-docs/). |
| **الشيفرة** | النواة والخادم والتطبيقات والموقع كلها في المستودع. راجع [إعداد بيئة التطوير](/ar/docs/contributing/development-setup/). |
| **الترجمات** | التطبيقات والموقع والتوثيق متوفرة بالإنجليزية والعربية (راجع [اللغات](/ar/docs/features/languages/)). التصحيحات مرحَّب بها، وتأتي لغات أخرى عبر [Weblate](/ar/docs/contributing/translations/). |
| **الأمان** | أبلغ عن الثغرات بشكل خاص كما هو موضح في `SECURITY.md`. لا تفتح issues عامة بشأنها. |

## القواعد الأساسية

- **لا إعلانات ولا متتبّعات ولا سكربتات من جهات خارجية** في أي مكان من المشروع.
- التغييرات في التشفير والمفاتيح والمصادقة والمزامنة والملء التلقائي تحتاج إلى قسم أمني في وصف طلب الدمج.
- التغييرات المهمة تُضاف لها مدخلة في [سجل التغييرات](/changelog/).
- كن لطيفًا. نلتزم [بقواعد السلوك](https://github.com/octap-app/octapass/blob/main/CODE_OF_CONDUCT.md).

## إقرار الأصل، لا اتفاقية CLA

يستخدم Octa Pass شهادة أصل المطوّر (Developer Certificate of Origin). وقّع كل commit:

```bash
git commit -s -m "docs: clarify recovery code rotation"
```

لا توجد اتفاقية ترخيص للمساهمين (CLA): تحتفظ بحقوق عملك وترخّصه بموجب MIT. راجع [الترخيص](/ar/docs/reference/license/).

## المساهمات بمساعدة الذكاء الاصطناعي

أدوات الذكاء الاصطناعي مرحَّب بها. على الوكلاء العاملين في المستودع اتباع `AGENTS.md`، ويبقى المساهم البشري مؤلف كل commit. راجع [التوثيق لوكلاء الذكاء الاصطناعي](/ar/docs/contributing/ai-agents/).
