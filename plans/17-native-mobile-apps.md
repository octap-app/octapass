# 17 — Native iPhone and Android apps

**Decision (maintainer, 2026-10-24):** the phone apps move from Tauri 2 (the web vault's screens in a web view) to fully native apps: **SwiftUI on iOS and iPadOS, Jetpack Compose on Android**, on the same Rust core. Until the native apps have every feature, the Tauri apps stay and get a native-feel polish (no zoom, no focus zoom, native touch behaviour; plan 14 History).

**Scope decision (maintainer, 2026-11-02):** everything planned for after 1.0 (roadmap phases 7 and 8, every P2 item in plan 01, all of plan 16) is inside 1.0. P2 still says what comes last, but it's required for 1.0. See [plan 09](09-roadmap.md). For this plan, that means phase 3 below is required for 1.0, and the 1.0 apps in the stores are the native ones, with the watch apps and plan 16's mobile tools added to them rather than to the Tauri app.

**Why:** on a real iPhone the web view shows: pinch-zoom on the whole UI, zoom on input focus, web scrolling and selection. Polish hides most of it, but lists, navigation, swipe actions, sheets, Dynamic Type, VoiceOver/TalkBack and keyboard handling are only first-class in native UI. The AutoFill and Credential Manager extensions are already native, so most native code already exists around the edges.

## Architecture

```text
SwiftUI app ─┐                       ┌─ iOS AutoFill extension (exists)
             ├─ OctaPassVault (UniFFI) ─ crates/octapass-mobile-vault ─ octapass-ffi ─ octapass-core
Compose app ─┘                       └─ Android Autofill / Credential Manager services (exist)
```

- **One Rust API for both apps.** The mobile vault crate (`crates/octapass-mobile-vault`: local store, sync, outbox, attachments, device unlock) is what the Tauri app's commands called. It gets a UniFFI interface, `OctaPassVault`, covering everything the screens need: account and sign-in (incl. two-step), vault and item CRUD for every type, search, sort and group, attachments, sharing, families, emergency access, share links, health and recovery map, masked email, generator, import and export, settings, devices and the security log, plus a change stream (callback interface) so lists update live. Same error codes and messages as the web vault.
- **No business logic in Swift or Kotlin.** The native layers do UI, platform services (Keychain/Keystore, biometrics, camera, file pickers, share sheet, haptics, notifications) and the HTTP client the FFI already asks for.
- **Strings:** English and Arabic from one source, generated into `Localizable.xcstrings` and Android `strings.xml` (plurals included), so the two apps and the web vault say the same thing.
- **Design:** platform-native components and navigation with the brand tokens (`brand/`, `packages/ui` tokens exported as Swift/Kotlin constants). iOS: NavigationStack/SplitView on iPad, swipe actions, sheets, Dynamic Type, SF Symbols. Android: Material 3 with the brand colours, predictive back, edge-to-edge.
- **Layout in the repo:** `apps/ios` (Xcode project: app + the existing AutoFill extension and Wi-Fi/QR code), `apps/android` (Gradle: app + the existing Autofill/Credential Manager services), both on the generated bindings. `apps/mobile` (Tauri) was removed on 2026-11-05 (History).
- **Where the API lives (decided in phase 1):** a crate of its own, `crates/octapass-mobile`, not more of `octapass-ffi`. The AutoFill extension and the Android services keep linking the small `octapass-ffi` (they run with tight memory limits and need only unlock and fill); the apps link `octapass-mobile`, which wraps the mobile vault crate and carries `octapass-ffi`'s C API too. Generated bindings: `apps/ios/Packages/OctaPassVault` (Swift package) and `apps/android/vault` (Kotlin sources and `jniLibs`). Strings and tokens: `apps/ios/Packages/OctaPassResources` and `apps/android/resources`, generated by `tools/native-resources`.

## Phases

1. **Vault API** (one agent): UniFFI `OctaPassVault` over the mobile vault crate, generated Swift and Kotlin bindings, binding tests in both languages against the real server, the strings pipeline, design tokens for Swift/Kotlin.
2. **iOS and Android in parallel** (one agent each, same screen list and order):
   - sign-up / sign-in / two-step / Recovery Kit, unlock (Face ID, Touch ID, passcode; fingerprint, face, screen lock), lock
   - item list with grouping and sorting, search, item view, editor for every type, favourites, trash
   - generator, one-time codes, QR (camera, photos, files), Wi-Fi Connect, attachments
   - health and recovery map, masked email
   - sharing, families, emergency access, share links
   - settings, devices, security log, import/export, delete account, languages (English, Arabic RTL)
   - the existing AutoFill extension and services moved into the new projects unchanged
3. **Parity check and switch:** a feature checklist against the web vault, native UI tests (XCUITest / Compose UI tests: these now test real native screens), screenshots in both languages and themes, then remove the Tauri phone app and update docs.

## Testing

Native UI tests drive the native screens directly (the "never coordinate-tap a web view" rule no longer applies to these apps). Rust logic stays covered by the vault crate's tests; each platform adds UI tests for every flow above and snapshot screenshots on the Simulator and the emulator.
