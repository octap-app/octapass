---
title: Phones can sync on a push, through an opt-in push relay
date: 2026-11-08
summary: The server wakes iPhones and Android phones when something changes, through a push relay that only ever sees a token and one word. Off by default, and not yet run with Apple's or Google's real services.
tags: [server, mobile, security, docs]
---

Until now, phones synced only when you opened Octa Pass and while it was open, and emergency access requests reached you by email only. Now a server can wake your phones:

- **A push says one word.** `sync` when something in a vault you can see changed, `alert` when someone shares a vault with you, invites you to a family, or adds you as an emergency contact, asks for emergency access, is denied or is given it. No account, email, vault, item or name is in it. On an `alert` the phone shows a notice in its own language and syncs.
- **The push relay** (`apps/push-relay`) holds the Apple and Google credentials, because only the app's publisher can wake its app. A self-hosted server registers with it once and then sends it tokens and the word. The relay stores no tokens and logs counts only. See [push relay](/docs/self-hosting/push-relay/).
- **Off by default.** Turn it on with `OCTAPASS_PUSH_RELAY=true` ([configuration](/docs/self-hosting/configuration/#push-sync)). `GET /v1/server-info` reports `pushRelay: true` only once the server is registered.
- **A locked phone syncs too**, downloading the changes still encrypted, so autofill and the next unlock have them.
- **Android** uses Firebase Cloud Messaging and nothing else from Firebase: no Analytics, no delivery metrics. Builds without Firebase settings sync as before.

Not done yet: nothing has gone through the real Apple or Google services (the tests use local stand-ins), and the Octa Pass relay isn't running, so for now push needs a relay you run with your own credentials. Design and decisions are in plans 03 and 04.
