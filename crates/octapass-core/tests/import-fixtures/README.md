# Import fixtures

Synthetic export files for the importers in `src/import/`, used by `tests/import.rs`. **None of this is real data**: every name, address, password and secret was made up for these files.

They cover Unicode, right-to-left text (Arabic), multi-line notes, quotes and commas inside CSV fields, empty fields and blank rows. The 10,000-row case is generated by the test itself rather than committed.

| File | Format |
|---|---|
| `chrome.csv` | Chrome / Edge / Brave password export |
| `firefox.csv` | Firefox password export |
| `safari.csv` | Safari / Apple Passwords export |
| `onepassword.csv` | 1Password 8 CSV |
| `onepassword-export.data.json` | The `export.data` file inside a 1Password `.1pux` (the test zips it) |
| `lastpass.csv` | LastPass, with `NoteType:` secure notes |
| `generic.csv` | A semicolon-separated CSV with made-up column names |
| `bitwarden.json` | Bitwarden unencrypted JSON |
| `bitwarden.csv` | Bitwarden CSV, as `individual-vault-export.service.ts` writes it (with `archivedDate`): folders, a favourite, several URIs in one cell, multi-line custom fields, a secure note, an archived login and an empty row |
| `bitwarden-org.csv` | Bitwarden organisation CSV (`collections` instead of `folder` and `favorite`) |
| `bitwarden-encrypted-pbkdf2.json`, `bitwarden-encrypted-argon2.json` | `bitwarden.json`, password protected (password `correct horse battery staple`) |
| `otpauth.txt` | `otpauth://` and `otpauth-migration://` links |

The encrypted Bitwarden files are made by `make-bitwarden-encrypted.mjs` with Node's own crypto, independently of the Rust code that reads them:

```sh
node crates/octapass-core/tests/import-fixtures/make-bitwarden-encrypted.mjs
```

## Credential Exchange Format (CXF)

These three are test vectors from other implementations, not synthetic files made here. They hold only made-up example data.

| File | Source |
|---|---|
| `cxf-spec-example.json` | The example payload in Appendix A of the FIDO Alliance [CXF v1.0 Proposed Standard (errata, 2026-03-09)](https://fidoalliance.org/specs/cx/cxf-v1.0-ps-errata-20260309.html), with one item of every credential type |
| `cxf-dashlane.json` | An export made by Dashlane (a bare `Account`, not a `Header`), from Bitwarden's SDK test resources: [`bitwarden/sdk-internal`](https://github.com/bitwarden/sdk-internal) `crates/bitwarden-exporters/resources/dashlane_export.json` at commit `5cf9198`, GPL-3.0 |
| `cxf-1password.json` | An export made by 1Password (also a bare `Account`), from the same place: `resources/1p_export.json`, GPL-3.0 |
| `cxf-apple-passwords.json` | Made for this project with Apple's own encoder: `ASExportedCredentialData` (AuthenticationServices, macOS 26.1 SDK) holding a login with a one-time code, a passkey (a fresh P-256 key), a card, a Wi-Fi network and a note, encoded with `JSONEncoder` and `.secondsSince1970`, which is what the iPhone and Mac apps pass on from the Credential Exchange import. Its dates are whole seconds; real exports have fractions, which `cxf_from_apple_with_fractional_dates` covers |
## Authenticator apps (Aegis, 2FAS, andOTP)

Used by `tests/import_aegis.rs`, `tests/import_2fas.rs` and `tests/import_andotp.rs`. Each plain file has TOTP codes (one matching the tests' existing GitHub login, one in Arabic, one with an emoji), HOTP, Steam and other code types, groups or tags, and one entry that must be skipped. Encrypted files use the password `correct horse battery staple`.

| File | Format |
|---|---|
| `aegis.json` | Aegis vault export, plain (vault version 1, content version 3) |
| `aegis-encrypted.json` | The same contents, encrypted (a biometric slot and a password slot) |
| `aegis-damaged.json` | Encrypted, with the contents' GCM tag changed: the password fits, the contents don't open |
| `2fas.2fas` | 2FAS backup, plain (schema version 4, Android) |
| `2fas-encrypted.2fas` | The same services, password protected (`servicesEncrypted` and `reference`) |
| `2fas-damaged.2fas` | Encrypted, with the salt and IV missing from `servicesEncrypted` |
| `andotp.json` | andOTP backup, plain |
| `andotp.json.aes` | The same, password encrypted (iterations ‖ salt ‖ nonce ‖ ciphertext) |
| `andotp-legacy.json.aes` | The same, in the older layout (SHA-256 of the password as the key) |
| `andotp-damaged.json` | `andotp.json` cut off in the middle of a character |

The encrypted and damaged files are made with Node's own crypto, independently of the Rust code that reads them. To keep the tests fast they use lighter key derivation than the apps (scrypt N = 2^10 instead of Aegis' 2^15; 10,000 PBKDF2 iterations instead of andOTP's 140,000 to 160,000). The layout is the same, and the importers read the settings from the file:

```sh
node crates/octapass-core/tests/import-fixtures/make-aegis.mjs
node crates/octapass-core/tests/import-fixtures/make-2fas.mjs
node crates/octapass-core/tests/import-fixtures/make-andotp.mjs
```

## Raivo OTP and Ente Auth

Used by `tests/import_raivo.rs`, `tests/import_ente.rs` and `tests/import_authenticator_reimport.rs`. Laid out as each app's own export code writes them: Raivo's `DataExportFeature.swift` ([raivo-otp/ios-application](https://github.com/raivo-otp/ios-application)), and Ente Auth's `export_widget.dart`, `code.dart` and `code_display.dart` with its CLI's `ente auth decrypt` ([ente-io/ente](https://github.com/ente-io/ente)). Password `correct horse battery staple`.

| File | Format |
|---|---|
| `raivo.json` | `raivo-otp-export.json`: every value is text; TOTP codes (GitHub, Arabic, emoji; SHA-1, SHA-256, SHA-512), a pinned one, HOTP and an entry without a secret |
| `raivo-aes256.zip` | `raivo.json` and an HTML page, encrypted by 7-Zip 25.01 as Raivo's export is: WinZip AES-256, stored |
| `raivo-aes128.zip` | The same with WinZip AES-128 and deflate |
| `ente-auth.txt` | The plaintext export: one `otpauth://` link per line with `codeDisplay` (note, tags, pinned, trashed, `lastUsedAt` in microseconds); TOTP, Steam and HOTP; a trashed code |
| `ente-auth-encrypted.json` | `ente-auth.txt` encrypted by libsodium as Ente Auth does: Argon2id, then one secretstream message with tag FINAL |
| `ente-auth-encrypted-message.json` | The same with tag MESSAGE, as older Ente versions wrote it |
| `ente-auth-encrypted-push.json`, `-two-chunks.json`, `-reordered.json` | A PUSH tag, two messages, and two messages swapped: all refused |

The archives and encrypted files are made with the apps' own kind of tools, independently of the Rust code that reads them: 7-Zip (from [7-zip.org](https://www.7-zip.org); the macOS build is one binary, `7zz`) and libsodium through PyNaCl. Neither is needed to run the tests. The Ente files use 8 MiB of Argon2 memory instead of Ente's 1 GiB, so the tests stay fast (the importer reads the settings from the file).

```sh
SEVENZIP=/path/to/7zz sh crates/octapass-core/tests/import-fixtures/make-raivo.sh
python3 -m venv /tmp/ente && /tmp/ente/bin/pip install pynacl
/tmp/ente/bin/python crates/octapass-core/tests/import-fixtures/make-ente.py
```

## Proton Pass, Dashlane and Enpass

Used by `tests/import_protonpass.rs`, `tests/import_dashlane.rs` and `tests/import_enpass.rs`. Laid out like the current exports of each app (checked against Proton Pass's own importer and test exports, and Bitwarden's importers). All data is made up.

| File | Format |
|---|---|
| `protonpass-data.json` | Proton Pass `data.json`: two vaults, nested folders, every item type (login with passkey, alias, note, card, identity, Wi-Fi, SSH key, custom), a trashed item, an item with attachments and an empty login |
| `protonpass.zip` | `protonpass-data.json` as `Proton Pass/data.json` in an uncompressed ZIP, like Proton's export |
| `protonpass-encrypted.zip` | `Proton Pass/data.pgp`, like the PGP-encrypted export: `protonpass-data.pgp` (passphrase `correct horse battery staple`) |
| `protonpass-data.pgp` | `protonpass-data.json` encrypted by OpenPGP.js 6.1.1 as Proton's `encryptPassExport` does: passphrase only, iterated and salted S2K with count byte 255, armored (SKESK v4, AES-256, SEIPD v1) |
| `protonpass-aead.pgp` | `protonpass.zip` encrypted by OpenPGP.js with Argon2 S2K and AEAD (SKESK v6, SEIPD v2) |
| `protonpass-gpg.pgp` | `protonpass-data.json` encrypted by GnuPG 2.5: binary, zlib-compressed |
| `protonpass-proton-mock.zip` | Proton's own encrypted test export, `packages/pass/lib/import/providers/protonpass/mocks/pgp-export.zip` in [ProtonMail/WebClients](https://github.com/ProtonMail/WebClients) (GPL-3.0). Its passphrase isn't published: the tests only open it as far as the passphrase |
| `protonpass.csv` | Proton Pass CSV, cards and identities as JSON in `note`, an empty row to skip |
| `protonpass-malformed.json` | Truncated `data.json` |
| `dashlane-credentials.csv`, `dashlane-securenotes.csv`, `dashlane-payments.csv`, `dashlane-ids.csv`, `dashlane-personalInfo.csv` | The CSV files of Dashlane's export |
| `dashlane.zip` | Those five files under Dashlane's names, plus `future-feature.csv`, which must be skipped with a warning |
| `dashlane.json` | Dashlane's older JSON export (`AUTHENTIFIANT`, `SECURENOTE`, `PAYMENTMEANS_CREDITCARD` …) |
| `dashlane-malformed.json` | Truncated JSON |
| `enpass.json` | Enpass JSON: nested folders, every category, password history, a trashed, an archived and an empty item, attachment data |
| `enpass-malformed.json` | Truncated JSON |

The ZIP files are made by two scripts from the files next to them. The PGP files are made first,
by OpenPGP.js (the library Proton Pass uses; not a dependency of this repository) and GnuPG,
independently of rPGP, which reads them:

```sh
npm install --prefix /tmp/openpgp openpgp@6.1.1
OPENPGP=/tmp/openpgp/node_modules/openpgp/dist/node/openpgp.mjs \
  node crates/octapass-core/tests/import-fixtures/make-protonpass-pgp.mjs
cd crates/octapass-core/tests/import-fixtures
gpg --homedir "$(mktemp -d)" --batch --yes --pinentry-mode loopback \
  --passphrase 'correct horse battery staple' --symmetric --cipher-algo AES256 \
  --s2k-digest-algo SHA512 --s2k-count 65536 --compress-algo zlib \
  -o protonpass-gpg.pgp protonpass-data.json
cd -
python3 crates/octapass-core/tests/import-fixtures/make-protonpass.py
python3 crates/octapass-core/tests/import-fixtures/make-dashlane.py
```

## KeePass and KeePassXC

Used by `tests/import_keepass.rs`.

| File | Format |
|---|---|
| `keepass.xml` | KeePass 2 XML export: nested groups (one Arabic), a Recycle Bin, tags, protected custom strings, entry history, an attachment, and every kind of one-time code setup (KeePassXC `otp`, KeePass `TimeOtp-*`, KeeOtp, KeeTrayTOTP, Steam) |
| `keepass-kdbx3.kdbx` | `keepass.xml` as KDBX 3.1: AES-KDF, AES-256, Salsa20, gzip. Password `correct horse battery staple` |
| `keepass-kdbx4-argon2d.kdbx` | KDBX 4.0: Argon2d, AES-256, ChaCha20, gzip. Password `correct horse battery staple` |
| `keepass-kdbx4-argon2id-keyfile.kdbx` | KDBX 4.1: Argon2id, ChaCha20 outer cipher, no compression. Password `كلمة المرور 🔑` and key file `keepass-keyfile.keyx` (XML key file, version 2.0) |
| `keepass-kdbx4-aes-twofish.kdbx` | KDBX 4.0: AES-KDF, Twofish, gzip. No password; key file `keepass-keyfile.txt` (any file, hashed) |

| `keepass.csv` | KeePass 2 "KeePass CSV (1.x)" export, with backslash-escaped quotes |

The databases are written by `make-keepass.py` from `keepass.xml`, with Python's own crypto (pycryptodomex, argon2-cffi and pykeepass's Twofish), independently of the Rust code that reads them. The script then opens each one with pykeepass as a check. KDF settings are tiny (1,000 AES rounds, 1 MiB Argon2) so the tests stay fast.

```sh
python3 -m venv /tmp/kp && /tmp/kp/bin/pip install pykeepass
/tmp/kp/bin/python crates/octapass-core/tests/import-fixtures/make-keepass.py
```
